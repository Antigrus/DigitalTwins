三节点多阵面信道计算流程
与三维姿态、坐标旋转原理

以当前 C 仿真工程为依据，说明从轨迹与节点配置出发，如何确定收发链路、构造节点/阵面/波束姿态，完成全局坐标到阵面局部坐标的转换，并计算方向增益、传播参数和复信道结果。

1. 工程模型与总流程

仿真对象由节点（Node）、节点轨迹（NodePosition）和节点所挂载的阵面（ArrayMount）组成。节点保存收发状态、运动姿态、指定发射阵面及波束扫描角；阵面保存相对节点的位置偏移、固定安装姿态、阵列参数和方向图缓存索引。

节点级信息节点 ID、启用状态、TX/RX 半双工状态、轨迹推导的速度与姿态、tx_array_id、波束扫描角。
阵面级信息阵面 ID、所属节点、相对位置 x/y/z、安装角 yaw/pitch/roll、阵元数、间距、频率和单阵元功率。
计算输出距离、传播时延、径向速度、多普勒、FSPL、Tx/Rx 增益、接收功率和复信道系数。
结果标识uint16_t index 编码有向节点对和两端阵面槽位，结果缓存按 index 直接寻址。
核心原则：节点姿态、阵面安装姿态、波束扫描姿态是三个不同层次。它们按坐标系从外到内组合，不能把扫描角直接写进安装角，也不能把阵面安装角当成节点姿态。

关键分支：谁发射、谁接收？

  • 每个节点是半双工节点，节点的 tr_state 决定该节点所有阵面的角色。
  • 节点对状态相反时，TX 节点指向 RX 节点形成有向链路；状态相同则跳过。
  • 指定 tx_array_id 时，发射端只使用 ID 匹配的阵面；接收端仍遍历其启用阵面。
  • tx_array_id=-1 表示发射端自动遍历所有启用阵面。

3. 坐标系定义

本工程采用右手三维坐标系，以全局坐标系作为位置、速度和传播方向的公共参考。矩阵作用于列向量，apply(R,v) 对应 \(Rv\)。

概念示意：阵面局部坐标系随节点运动姿态和安装姿态一起转动；实际方向由旋转矩阵严格确定。
坐标系定义 / 用途
全局坐标系 G节点位置、轨迹、速度、Tx→Rx 传播方向；当前约定 Z 轴向上。
节点坐标系 N节点局部 +X 轴沿运动方向；姿态由 heading、pitch、roll 描述。
阵面坐标系 A阵面局部 +X 为法向/波束正前方，+Y 为水平阵列轴，+Z 为垂直阵列轴。
扫描后波束坐标系 B在阵面局部坐标系中施加扫描方位和俯仰后的指向坐标系。
坐标约定必须一致：方向图表的角度定义为 theta 仰角、phi 方位角，且阵面局部 +X 是 broadside。若硬件方向图使用不同的法向、方位零点或正方向，需要统一修改角度映射，不能只改 CSV 数值。

4. 三层姿态设计与使用

4.1 节点运动姿态 Node Attitude

当前仿真不从配置文件直接读取节点姿态，而是由轨迹相邻采样点计算速度，再由速度方向推导节点朝向。对轨迹点 \(P_i=(x_i,y_i,z_i)\)、\(P_{i+1}\) 和时间间隔 \(\Delta t\)：

v = (Pi+1 − Pi) / Δt
heading = atan2(vy, vx)； pitch = atan2(vz, √(vx²+vy²))； roll = 0
  • heading：水平面内绕全局 Z 轴的航向角，正方向从 +X 朝 +Y。
  • pitch：运动方向相对水平面的仰角；向上运动为正。
  • roll：当前模型固定为 0，未模拟机体绕前向轴滚转。

因此，节点局部 +X 经节点旋转后指向轨迹速度方向。若速度近似为零，代码保留上一次姿态，不重新计算。

4.2 阵面安装姿态 ArrayMount.initial_attitude

阵面安装姿态描述阵面相对节点坐标系的固定安装角，CSV 字段为 yaw,pitch,roll。它用于表达阵面在平台上的机械安装方向，不随波束扫描变化。

  • yaw：阵面相对节点绕局部 Z 轴的旋转。
  • pitch：阵面相对节点绕局部 Y 轴的旋转；代码使用负 pitch 角构造矩阵。
  • roll：阵面相对节点绕局部 X 轴的旋转。

阵面相对节点的位置偏移 x,y,z 与安装姿态是两类数据：位置偏移用于计算阵面相位中心的位置；安装姿态用于计算阵面朝向。当前偏移向量按节点坐标系表达。

4.3 波束扫描姿态 BeamDirection

节点字段 beam_direction.azimuth/elevation 是扫描角，定义在每个阵面的局部坐标系中。它在固定安装姿态之后叠加，当前同一节点的阵面共用这组扫描角。

  • 扫描 azimuth：绕阵面局部 Z 轴转动，使 +X 波束轴朝局部水平面内的方位方向偏转。
  • 扫描 elevation：通过绕局部 Y 轴的负角旋转，使 +X 波束轴向局部 +Z 抬起。
  • 扫描角为 0、0 时，波束轴与阵面安装后的局部 +X 法向一致。
Rbeam = Rnode · Rmount · Rscan
使用建议：机械安装角写入 arrays.csv；动态平台姿态由轨迹更新；电子扫描角写入 nodes.csv 的 beam_azimuth_deg/beam_elevation_deg。三者职责分离，修改扫描角不会覆盖安装姿态。

4.4 三种姿态的作用边界

姿态来源改变什么不应承担的职责
节点姿态轨迹速度方向整个节点及所挂阵面的全局朝向；阵面位置偏移的全局方向不表达阵面独立机械安装角或电子扫描角
阵面安装姿态arrays.csv阵面相对节点的固定朝向不应随每次波束扫描动态覆盖

5. 旋转矩阵的数学原理

5.1 为什么使用旋转矩阵

三维姿态可以理解为一个坐标系相对另一个坐标系的方向关系。旋转矩阵把一个坐标系中的向量映射到另一个坐标系。使用列向量时，若 \(v_A\) 是阵面局部坐标，\(v_G\) 是全局坐标，则：

vG = RG←A vA

旋转矩阵的列向量分别是局部 X、Y、Z 三个单位轴在目标坐标系中的表达。纯旋转矩阵满足正交性：

RTR = I， det(R)=+1， 因此 R−1 = RT

所以全局向量变换回局部坐标时，不必求一般矩阵逆，只需乘旋转矩阵的转置。

5.2 绕三个坐标轴的基本旋转

代码中的 rx、ry、rz 均使用右手定则，角度传入弧度。对列向量：

Rx(α) = [ [1,0,0], [0,cosα,−sinα], [0,sinα,cosα] ]
Ry(β) = [ [cosβ,0,sinβ], [0,1,0], [−sinβ,0,cosβ] ]
Rz(γ) = [ [cosγ,−sinγ,0], [sinγ,cosγ,0], [0,0,1] ]

5.3 本工程欧拉角顺序

math3d.c 中的 euler() 明确采用以下乘法顺序：

R(heading,pitch,roll) = Rz(heading) · Ry(−pitch) · Rx(roll)

矩阵乘法不满足交换律：一般而言 \(R_xR_y \ne R_yR_x\)。因此欧拉角顺序是工程定义的一部分，不能任意交换。当前代码中 pitch 使用负号，是为了让局部 +X 轴在正 pitch 时向全局 +Z 抬起。

验证这一点：令 roll=0，先将局部前向单位向量 \(e_x=[1,0,0]^T\) 旋转：

Rz(h)Ry(−p)ex = [cos p cos h, cos p sin h, sin p]T

这与轨迹速度方向的 heading、pitch 定义一致。

5.4 坐标层级的矩阵组合

RG←N = Rnode
RG←A = RG←N RN←A = Rnode Rmount
RG←B = Rnode Rmount Rscan

从右向左理解：先在最内层阵面坐标系施加扫描旋转，再经过阵面安装旋转，最后经过节点运动旋转，得到全局方向。代码中的 compose_rot(a,b) 返回 \(a·b\)。

常见错误：把矩阵乘法顺序反过来、对全局方向使用 R 而不是 Rᵀ、把角度制直接传给 sin/cos、或混淆主动旋转向量与被动旋转坐标系。上述任一问题都可能让波束指向偏离预期。

6. 坐标转换与方向角计算

6.1 阵面全局位置

阵面偏移 \(p_{offset}\) 在节点局部坐标系中给出。当前代码先使用节点旋转矩阵将偏移转换到全局，再与节点全局位置相加：

Parray,G = Pnode,G + Rnode poffset,N

注意：位置偏移只乘节点姿态矩阵，不乘阵面安装姿态矩阵。因为配置中的偏移描述阵面安装点在节点坐标系中的位置，而不是阵面自身局部坐标中的偏移。

6.2 Tx 到 Rx 的全局传播方向

ΔP = Prx,array − Ptx,array； d = ||ΔP||； u = ΔP / d

其中 \(u\) 是 Tx 指向 Rx 的全局单位向量。发射端沿 \(u\) 方向观察接收端；接收端的入射方向则是 \(-u\)。因此 Rx 方向增益调用时传入反向向量。

6.3 转换到波束局部坐标

发射端和接收端分别构造自己的总旋转矩阵 \(R_{beam}\)。全局方向转到局部方向：

ulocal = RbeamT uglobal

代码实现对应 apply(transpose(r), direction_global)。接收端则使用 direction_global = -u。这一步将“世界里传播方向指向哪里”转换为“从阵面自身看，来波/去波来自哪个局部角度”。

6.4 从局部方向向量得到 theta、phi

本工程方向图约定：theta 是仰角，phi 是相对阵面法向的方位角；局部 +X 是法向，+Y 为水平阵列轴，+Z 为垂直阵列轴。

theta = atan2(zlocal, √(xlocal²+ylocal²))
phi = atan2(ylocal, |xlocal|)

计算结果转换为度后，送入 beam_gain()。该函数将角度限制在 −90° 到 +90°，并对 181×181 方向图做双线性插值。

物理解释：姿态矩阵负责把方向向量表达在正确的阵面局部坐标系里；theta/phi 只负责把局部向量映射成方向图索引。两步不能混为一谈。

7. 信道参数计算

7.1 距离与传播时延

d = ||Prx,array − Ptx,array||； τ = d/c

其中 \(c\) 为光速常数 C0。当前模型为单径自由空间 LOS。

7.2 径向速度与多普勒

vr = (vrx − vtx) · u
fd = −vr fc / c

这里 \(u\) 是 Tx 指向 Rx 的单位向量。按当前符号约定，\(v_r>0\) 表示两端沿链路方向相对远离，对应负多普勒；靠近时符号相反。

7.3 自由空间路径损耗

FSPL = 20 log10(4π d fc / c)

Tx/Rx 工作频率不一致（容差 1e-6 MHz）时，该阵面组合被判为不可用。

7.4 方向增益与接收功率

方向图缓存保存线性场幅度 \(A\)，而不是 dB。代码将其转换为：

Gtx,dB = 20log10(Atx)； Grx,dB = 20log10(Arx)
Pr = Pelement + 10log10(MtxNtx) + Gtx + Grx − FSPL

发射阵列阵元数 \(M_{tx}N_{tx}\) 用于把单阵元发射功率换算为阵列总输入功率。当前为理想均匀同相馈电模型，未包含馈线损耗、阵元方向图、互耦、极化失配和硬件幅相误差。

7.5 复信道系数

|h| = √(MtxNtx) AtxArx λ/(4πd)
∠h = −2π fc τ； h = |h|[cos(∠h)+j sin(∠h)]

结果写入 h.re、h.im。该 h 以单个 Tx 阵元输入信号为参考，已包含理想相干 Tx 阵列合成、Rx 方向响应和自由空间传播项；与链路预算结合时需保持功率参考一致，避免重复乘阵元数。

8. 波束表与信道结果缓存

8.1 波束表缓存

全局 g_beam_cache 按阵列参数组合共享方向图。缓存键包括横/纵阵元数、横/纵间距和工作频率。阵面安装角、节点姿态和扫描角不属于缓存键，因为它们只影响方向向量在局部坐标系中的表达，不改变阵列自身的方向图表。

表大小为 181×181，theta、phi 均覆盖 −90° 到 +90°。查询时使用双线性插值。方向图计算使用均匀矩形阵列可分离形式，等价于二维阵元相位复数求和的幅度表达。

8.2 uint16_t 链路索引

位段字段说明
[11:10]txid2 bit 节点 ID
[9:8]rxid2 bit 节点 ID
[7:4]tx_array_slot发射阵面在 tx->arrays[] 中的槽位 0～15
[3:0]rx_array_slot接收阵面在 rx->arrays[] 中的槽位 0～15
[15:12]保留当前未使用

索引空间为 4096 项。缓存结构使用 links[index] 直接定位结果，并用 occupied 位图标识该索引是否已登记；因此查询为 O(1)，且能区分“没有结果”和“已登记但 valid=0”。

索引约束：当前编码函数要求节点 ID 在 0～3 且 TX/RX 节点不同；每端最多 16 个阵面。4 bit 阵面字段保存的是节点数组中的槽位，不是外部阵面 ID。节点 ID 若改为更大或非 0～3 的值，必须增加 ID 到编码值的映射或重新设计位宽。

10. 使用边界与检查建议

  1. 姿态顺序固定：当前为 Rz(heading)·Ry(−pitch)·Rx(roll)，扫描为 Rz(azimuth)·Ry(−elevation)。修改前应使用已知向量验证。
  2. 角度单位：配置角度以度为单位；构造矩阵时转换为弧度。不要把度直接传给 sinf/cosf。
  3. 节点静止：速度模长很小时保留旧姿态；若场景需要静止时指定朝向，应增加独立姿态输入或静止姿态配置。
  4. roll 的局限：当前轨迹推导姿态把 roll 固定为 0，不能描述平台真实滚转；可后续接入姿态传感器或姿态关键帧。
  5. 阵面偏移：当前 offset 在节点坐标系中表达，仅乘 R_node。若未来改成阵面局部偏移，必须同步调整位置变换。
  6. 接收方向：接收端方向图使用 −u；若误用 +u，会把接收波束角度算反。
  7. 局部角定义：当前 phi 使用 atan2(y,|x|)，theta 使用仰角定义。需要与硬件方向图生成程序的角度定义逐项核对。
  8. 模型适用范围：当前是单径 LOS 自由空间模型，不含反射、多径、遮挡、阴影衰落和噪声。
  9. 缓存容量：方向图缓存默认最多 8 张；结果索引空间固定 4096 项。两种缓存的容量和键定义不同。
  10. 并发访问：若计算任务与通信/上传任务并发读写结果缓存，应使用临界区、互斥锁或双缓冲。

heading=0°, pitch=30°, roll=0°[cos30°,0,sin30°]正 pitch 抬高局部 +X
scan az=90°, el=0°阵面局部 [0,1,0]扫描方位绕局部 Z 轴
scan az=0°, el=30°阵面局部 [cos30°,0,sin30°]扫描俯仰向局部 +Z 抬高

11. 对应源码与阅读顺序

文件重点内容
include/sim.hNode、ArrayMount、Attitude、BeamDirection、ChannelResult、链路索引定义。
src/main.c初始化方向图缓存、按仿真时刻更新状态、枚举有向节点链路与阵面组合。
src/trajectory.c轨迹读取、线性插值、速度计算和节点 heading/pitch/roll 更新。
src/math3d.c基本向量运算、Rx/Ry/Rz、欧拉角顺序、矩阵组合与矩阵向量乘法。
src/channel.c阵面全局位置、总姿态矩阵、全局到局部方向转换、theta/phi、信道参数计算。
src/beam.c方向图生成与复用、双线性插值、按 uint16_t index 直接缓存信道结果。
src/config.c节点、阵面、轨迹配置解析及指定发射阵面检查。
阅读建议：先看 trajectory.c 理解节点姿态来源，再看 math3d.c 理解矩阵约定，随后阅读 channel.c 中的 array_gain_amplitude()。这条路径最容易把“姿态如何影响方向图查询”串起来。
