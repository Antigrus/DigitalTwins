三节点多阵面动态信道仿真工程

C11 模块化结构 · 头文件与源文件接口边界 · DSP 移植建议

1. 重构目标

将原本集中在 sim.h 中的结构体、宏和所有函数声明拆分到独立模块接口。每个可复用功能模块采用同名头文件/源文件配对，便于后续按功能移植、单独测试和替换平台相关实现。

公共类型集中定义；模块函数声明归属模块头文件；全局变量在一个源文件中定义，在对应头文件中使用 extern 声明；头文件之间尽量不形成业务依赖环。

2. 新目录结构

DigitalTwins/
├── include/
│   ├── sim_types.h       # 公共类型、常量和容量定义
│   ├── config.h          # 配置模块接口
│   ├── trajectory.h      # 轨迹模块接口
│   ├── math3d.h          # 三维数学模块接口
│   ├── beam.h            # 波束表和结果缓存模块接口
│   ├── channel.h         # 信道计算模块接口
│   └── sim.h             # 兼容性聚合头文件
├── src/
│   ├── main.c            # 程序入口和流程编排
│   ├── config.c          # INI/CSV 解析
│   ├── trajectory.c      # 轨迹插值、速度和节点姿态
│   ├── math3d.c          # 向量、矩阵和旋转
│   ├── beam.c             # 方向图生成、查询和缓存
│   └── channel.c          # 阵面几何与 LOS 信道
├── config/
├── docs/
├── Makefile
└── README.md

config、trajectory、math3d、beam、channel 均为一一对应的模块对。main.c 是应用程序入口，不提供供其他模块调用的 API，因此不创建无实际用途的 main.h。

3. 模块职责

模块头文件 / 源文件职责和主要接口
公共类型sim_types.hNode、ArrayMount、SimConfig、ChannelResult 等跨模块数据结构及容量宏。
配置config.h / config.cconfig_load()、config_free()、find_node()、find_pos()。
轨迹trajectory.h / trajectory.cload_trajectory()、update_state()，负责位置插值、速度和由速度推导的节点姿态。
数学math3d.h / math3d.c向量运算、Mat3、欧拉旋转矩阵构造和矩阵向量乘法。
波束/缓存beam.h / beam.c方向图生成、配置去重、双线性插值、信道结果直接索引缓存。
信道channel.h / channel.c阵面相位中心、局部方向角、距离、时延、多普勒、路径损耗、功率和复信道。
应用入口main.c命令行解析、初始化、仿真循环和链路/阵面组合枚举。

4. 依赖关系

main.c
 ├── config.h ───── config.c ──┬── math3d.h
 │                             └── trajectory.h
 ├── trajectory.h ─ trajectory.c ── math3d.h
 ├── math3d.h ───── math3d.c
 ├── beam.h ─────── beam.c
 └── channel.h ──── channel.c ──┬── math3d.h
                                └── beam.h

所有模块接口共享 sim_types.h

模块头文件只包含公共类型头文件；如果某个源文件需要调用其他模块的函数，再在该源文件中包含相应接口。这样可以减少循环包含，并使依赖关系在源文件顶部清晰可见。

5. 头文件规范

头文件保护

#ifndef CONFIG_H
#define CONFIG_H
#include "sim_types.h"
int config_load(SimConfig *config, const char *ini_path);
#endif

全局变量

/* beam.h：声明 */
extern BeamTableCache g_beam_cache;

/* beam.c：唯一实体定义 */
BeamTableCache g_beam_cache;

不要在头文件中定义普通全局变量。公共结构体放入 sim_types.h；只在单个模块内部使用的辅助函数和私有类型应保留在对应 .c 文件中并尽可能声明为 static。

6. 兼容性与编译

include/sim.h 保留为聚合头文件，内部包含所有模块头文件，旧代码暂时可以继续 #include "sim.h"。新代码应按需包含具体模块头文件，以减少编译依赖。

make clean
make
./channel_sim config/simulation.ini
./channel_sim config/simulation.ini --time 2.5

Makefile 自动收集 src/*.c 和 include/*.h，新增功能模块时按同名方式增加头文件和源文件即可。

7. 面向 DSP / 嵌入式移植

  1. 算法移植优先带走 sim_types.h、math3d.*、trajectory.*、beam.*、channel.*；上位机已解析配置时可不移植 config.*。
  2. 将配置加载替换为协议解析后的结构体填充；算法层不直接依赖 UDP/TCP。
  3. 将控制台输出替换为目标平台日志或结果上报接口。
  4. 检查方向图缓存和结果缓存的静态内存占用，必要时放入 DDR 或专用存储段。
  5. 多任务并发读写结果缓存时使用临界区、互斥锁或双缓冲。
